# Test matrix: slash-command parser and canonical schema validator

Scope is limited to backend parsing and canonical validation for the external
`mock` plugin. The integration cases use the public command/per-turn
route and the real DSH AgentLoop/ToolRuntime boundary; they do not invoke a
tool implementation from the parser, validator, or adapter.

Shared fixtures from `test.md`: `probe_tool`, `ordered_tool`, `needs_value`,
`real_provider_probe`, `session-A`, `session-B`, an in-memory file system, and
a recording session/event store. For every rejected input, assert the named
error class, no plan/queue entry, no emitted tool-call block, no ToolRuntime
invocation, no durable `tool/call` or `tool/result`, and a terminal non-busy
state. Coverage tags in the fixture column are `positive`, `negative`,
`boundary`, `security`, or `malformed`.

## 1. Slash-command parser

The parser produces a canonical script for accepted `/mock run` and
`/mock replay` commands. It checks command grammar and JSON syntax only;
unknown-tool and tool-schema decisions remain with the real ToolRuntime.

| ID | Level | Fixture/input | Expected result | Forbidden shortcut detected |
| --- | --- | --- | --- | --- |
| CMD-01 | unit | **positive** — `/mock run probe_tool({})` | Produces exactly one `{tool:"probe_tool", args:{}}` step; no wait is inserted. | Parser executing `probe_tool` or synthesizing queue timing. |
| CMD-02 | unit | **boundary** — `/mock run probe_tool({"nested":{"a":[true,null,"雪"]},"escaped":"\\\"","n":9007199254740991})` | Arguments deep-equal the JSON data, including Unicode, escapes, arrays, null, and the largest safe integer. | `eval`/`Function`, string coercion, unsafe integer rounding, or code execution. |
| CMD-03 | unit | **positive** — `/mock run  probe_tool( { "value" : "ok" } )` with leading/trailing and internal JSON whitespace | Canonical args equal `{"value":"ok"}`; whitespace is not retained as data. | Treating whitespace as a shell token or passing raw JSON text to a tool. |
| CMD-04 | unit | **positive** — `/mock run [probe_tool({"value":"a"})\n ordered_tool({"label":"b"}) probe_tool({"value":"c"})]` | Produces one nonempty parallel step with three calls in source order. | Turning siblings into sequential steps or inserting inter-member waits. |
| CMD-05 | integration | **positive/runtime boundary** — `/mock run syntactically_valid_but_missing({})` | Parser accepts the shape; AgentLoop emits the call and real ToolRuntime returns `UNKNOWN_TOOL`; no parser-side registry rejection or execution. | Parser-side tool lookup, pre-approval, or direct adapter/tool invocation. |
| CMD-06 | unit | **negative** — `/mock run probe_tool({'value':'x'})`; `probe_tool({"value":1,})`; `probe_tool({"value":NaN})`; `probe_tool({"value":undefined})` | Each is rejected as `INVALID_COMMAND` with a useful position; no plan starts. | JavaScript-compatible parsing, comment/trailing-comma tolerance, or `eval`. |
| CMD-07 | unit | **security** — `/mock run probe_tool(({}))`; `/mock run probe_tool(` + "`\"x\"`" + `)`; `/mock run probe_tool(new Object())`; `/mock run probe_tool(1+1)` | Rejects expressions, template literals, constructors, and arithmetic; never evaluates them. | `eval`, `new Function`, expression parsing, or shell execution. |
| CMD-08 | unit | **malformed** — `/mock run probe_tool({"value":"x"}`; `/mock run probe_tool({}) probe_tool({})`; `/mock run probe_tool({}); /mock run probe_tool({})` | Rejects unmatched delimiters and all extra/sequential top-level statements as one invalid command. | Prefix parsing that accepts a valid first call and ignores trailing input. |
| CMD-09 | unit | **negative** — `/mock run probe_tool([])`; `/mock run probe_tool(null)`; `/mock run probe_tool("x")`; `/mock run probe_tool(1)` | Rejects because tool arguments must be a JSON object, not an array, scalar, or null. | Passing parser output directly to ToolRuntime or silently wrapping/coercing values. |
| CMD-10 | unit | **negative** — `/mock run probe_tool({"value":"x"}) --wait 10`; `/mock run wait(10)`; `/mock run probe_tool({"value":"x"}); wait(10)`; `/mock run [probe_tool({}), wait(10)]` | Rejects `--wait`, `wait(...)`, wait objects, and semicolon-separated timing syntax; no call is emitted. | Treating wait syntax as a tool call or adding a private timing grammar to `/mock run`. |
| CMD-11 | unit | **malformed** — `/mock run ({})`; `/mock run ( {"x":1} )`; `/mock run probe-tool({})`; `/mock run probe_tool({})|Out-File x` | Rejects missing/invalid tool names and command separators, pipes, or redirection. | Shell-tokenization or accepting a tool name by stripping unsafe characters. |
| CMD-12 | unit | **malformed** — `/mock run [probe_tool({}) ordered_tool]`; `/mock run [probe_tool({}) {"tool":"x","args":{}}]`; `/mock run [probe_tool({}), ordered_tool({})]` | Rejects incomplete items, object-shaped items, and comma-separated syntax; every bracket member must be a complete call expression. | Best-effort item dropping, comma-as-JSON parsing, or partial parallel execution. |
| CMD-13 | unit | **security** — `hello /mock run probe_tool({"value":"x"}) wait` and JSON input `/mock run probe_tool({"text":"/mock wait | del *"})` | First input remains ordinary non-command text; second accepts only inert JSON string data. Neither invokes the mock parser for embedded text nor executes shell syntax. | Substring scanning, recursive command interpretation, or shell execution from argument strings. |
| CMD-14 | integration | **positive/routing** — Send `/mock run probe_tool({"value":"x"})` once as a followup and once as a steer while a real turn is active. | Both arrive as the next turn with equivalent canonical plans and `{provider:"mock", model:"mock"}` route overrides; current real turn is unchanged. | Separate followup/steer execution modes, private loops, or persistent model mutation. |
| CMD-15 | integration | **boundary/isolation** — Concurrently parse `/mock run probe_tool({"value":"A"})` in `session-A` and `/mock run probe_tool({"value":"B"})` in `session-B`. | Each session gets a distinct turn-local plan/cursor and exact args; completion or cleanup in A cannot consume B. | Global pending command/script state or fallback session keys. |
| CMD-16 | integration | **negative/routing** — Submit `/mock run probe_tool({` followed by normal text `hello`. | First request reports `INVALID_COMMAND` and becomes idle; `hello` routes to `real_provider_probe` with no mock state left behind. | Sticky global `mockEnabled`, plan creation before validation, or intercepting non-slash text. |
| CMD-17 | unit | **positive/path** — `/mock replay "C:\\test fixtures\\one.jsonl" --overwrite-wait-time-ms 250` | Parses one quoted path and one integer option; quotes are removed once, path characters remain intact, and the approved reader is selected without modifying the source. | Shell splitting, path rewriting, physical conversion-file creation, or treating the option as an overwrite flag. |
| CMD-18 | unit | **boundary/security** — `/mock replay one.json --overwrite-wait-time-ms` or values `-1`, `1.5`, `1e2`, `NaN`, `Infinity`, `0x10`, `9007199254740992`; duplicated/unknown wait flags | Rejects before file read or queue creation; accepts only one non-negative safe integer, including `0` and `250`. | Numeric coercion/rounding, unsafe integer acceptance, duplicate-option precedence, or source mutation. |

## 2. Canonical script/schema validator

The shared validator is the only structural boundary for self-authored JSON and
all converter output. It validates the canonical shape, strict object fields,
tool-name syntax, JSON-object arguments, parallel restrictions, and wait
placement/value rules. Tool-specific argument schemas are intentionally left to
the real ToolRuntime.

| ID | Level | Fixture/input | Expected result | Forbidden shortcut detected |
| --- | --- | --- | --- | --- |
| SCH-01 | unit | **positive** — `{"type":"dsh-mock-script","version":1,"steps":[{"tool":"probe_tool","args":{}}]}` | Accepts and returns one canonical tool step with stable field names/order. | Accepting an unversioned/internal shape or bypassing the shared validator. |
| SCH-02 | unit | **positive/boundary** — Tool args contain `{ "value": [1, true, null, {"u":"雪"}], "escaped":"\\\"" }`. | Accepts the JSON object and preserves nested data exactly without changing types. | Evaluating JSON as code, flattening/coercing values, or validating only top-level fields. |
| SCH-03 | unit | **positive/boundary** — `steps`: tool `a`, `{ "wait": 0 }`, parallel `[b,c]`, `{ "wait": 250 }`, tool `d`. | Accepts; waits are between executable steps, and executable-step count is three (tool, group, tool). | Treating waits as tools, rejecting valid zero waits, or counting parallel members as top-level steps. |
| SCH-04 | unit | **positive** — `{"parallel":[{"tool":"ordered_tool","args":{"label":"a"}},{"tool":"ordered_tool","args":{"label":"b"}}]}` | Accepts one nonempty parallel step and retains member order and membership. | Converting a parallel group to sequential steps or adding validator-owned inter-member delay. |
| SCH-05 | unit | **positive/boundary** — Tool names `probe-tool`, `probe_tool`, and a name at the documented DSH identifier limit; one name just outside the limit. | Accepts exactly the names permitted by the public DSH rule and rejects the out-of-bound name with its path. | Applying a looser ad-hoc regex or silently sanitizing tool names. |
| SCH-06 | unit | **negative** — Root values `null`, `[]`, `"x"`, `1`; `{}`; `{"type":"DSH-MOCK-SCRIPT","version":1,"steps":[]}`; version `2`. | Rejects with `INVALID_SCRIPT` at the root/type/version path; no queue compilation. | Truthiness checks, case folding, defaulting a missing version, or accepting future versions. |
| SCH-07 | unit | **malformed** — `{"type":"dsh-mock-script","version":1}`; `steps:null`; `steps:{}`; `steps:[]`. | Rejects missing/non-array/empty steps with a path-aware `INVALID_SCRIPT`. | Treating an absent script as a no-op or allowing queue creation with no executable step. |
| SCH-08 | unit | **malformed** — Steps `null`, `1`, `[]`, `{}`, and `{"wait":100,"tool":"x"}`. | Rejects every invalid step variant and identifies the failing `steps[i]`. | Skipping malformed entries, inferring a step kind from partial fields, or partial replay. |
| SCH-09 | unit | **negative/boundary** — `{"tool":"","args":{}}`; missing `tool`; `{"tool":1,"args":{}}`; `{"tool":"bad name","args":{}}`; missing `args`. | Rejects invalid/empty/non-string names and missing fields at the exact step path. | Coercing names, accepting empty names, or relying on the registry to repair malformed structure. |
| SCH-10 | unit | **negative** — Tool args are `null`, `[]`, `"x"`, `1`, `true`, or missing. | Rejects because `args` must be a JSON object; no ToolRuntime call occurs. | Wrapping scalars, treating arrays as objects, or deferring a malformed canonical shape to execution. |
| SCH-11 | unit | **negative/security** — Root has `"mock":true`; tool step has `"delay":1`; wait step has `"tool":"x"`; parallel member has `"extra":1`. | Rejects unknown sibling fields instead of dropping them or selecting a conflicting step kind. | Permissive object spreading, silent field dropping, or a second private schema. |
| SCH-12 | unit | **boundary** — Wait fixtures: leading `{ "wait":0 }`, trailing wait, consecutive waits `100,0`, wait as only step, and valid `tool -> wait:0 -> tool`. | Rejects every illegal placement and accepts only the strictly-between valid case. | Compiling waits at the queue boundary, merging consecutive waits, or treating a wait as an executable step. |
| SCH-13 | unit | **boundary/negative** — Wait values `-1`, `1.5`, `"250"`, `true`, `null`, `9007199254740992`, plus parser-produced `NaN`/`Infinity`; compare `0` and `9007199254740991`. | Accepts `0` and the largest safe integer; rejects negative, fractional, string, non-finite, and unsafe values before compilation. | Numeric coercion, rounding, unsafe timer values, or allowing non-JSON numeric sentinels. |
| SCH-14 | unit | **negative/malformed** — `{"parallel":[]}`; parallel containing a wait, nested parallel, missing args, or a scalar member. | Rejects empty groups and every non-tool member at the member path; no group is partially queued. | Flattening nested groups, ignoring invalid siblings, or inserting waits inside a parallel response. |
| SCH-15 | unit | **security** — Duplicate root key `"version":1,"version":2`; root/step `"__proto__"`, `"constructor"`, or `"prototype"` fields. | Under this matrix’s explicit duplicate/unsafe-key policy, rejects ambiguity and pollution keys with no prototype mutation. | Last-key-wins ambiguity, unsafe object merge, prototype pollution, or execution of attacker-controlled fields. |
| SCH-16 | unit | **security** — Valid args include `{"payload":{"__proto__":{"polluted":true}},"code":"process.exit()"}`. | Canonical validation treats values as inert JSON data; output preserves the data, `Object.prototype` is unchanged, and no code runs. | Recursive `eval`, unsafe deep merge, or confusing tool arguments with executable schema/configuration. |
| SCH-17 | unit | **boundary/security** — A deeply nested object beyond the configured depth, an oversized JSON value, and an in-memory cyclic object passed directly to the validator. | Fails deterministically with `INVALID_SCRIPT`/size diagnostic without hanging or stack overflow; cyclic data is never queued. | Unbounded recursion, crash-on-input, implicit serialization, or accepting non-JSON memory graphs. |
| SCH-18 | unit | **positive/integrity** — Validate a mutable source object, mutate its `steps[0].args` afterward, then serialize/parse validator output. | Canonical result/compiled plan remains unchanged; serialize/parse round-trip is deep-equal with one stable public shape. | Retaining caller-owned references, lazy validation, noncanonical aliases, or mutation after validation. |
| SCH-19 | integration | **shared-boundary** — Feed the same invalid canonical shape (`parallel:[{"tool":"probe_tool"}]`) through self-authored JSON and a DSH JSONL converter. | Both paths invoke the same validator, return equivalent `INVALID_SCRIPT` category/path context, and reach neither AgentLoop nor ToolRuntime. | Converter-specific weaker validation, duplicate schema logic, or queueing plausible-but-invalid adapter output. |
| SCH-20 | integration | **runtime-boundary** — Valid canonical `{"tool":"needs_value","args":{"value":1,"extra":true}}`. | Canonical validator accepts the object shape and passes it to real ToolRuntime, which returns normal `INVALID_ARGS`; no plugin-side schema rejection or direct execution. | Duplicating tool schemas in the canonical validator, pre-approving args, or bypassing the real runtime. |
