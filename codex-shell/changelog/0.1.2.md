# 0.1.2

## Added

- Added eight reusable E2E test prompts covering trivial commands, nonzero
  exits, stdin round trips, delayed output, natural exits, token-capped output,
  interactive sessions, and concurrent-session cleanup.
- Added regression coverage for output retention, natural-exit notifications,
  memory cleanup, Windows pipe lifecycle behavior, and cross-call polling.

## Fixed

- Completed sessions are no longer removed immediately when a token-capped
  read still has buffered output. Terminal pages can now include both
  `exit_code` and `session_id`; empty `write_stdin` polls retrieve the remaining
  output before the session is released.
- Output produced between `exec_command` and the next `write_stdin` poll remains
  available and is not silently discarded.
- Natural-exit notifications now direct the owner to poll with the original
  session ID and empty `chars`.
- Session listeners, stdin handles, process handles, and bounded output state
  are released on completion, owner disposal, and plugin disposal.

## Behavior

- Pipe transport remains the default on Windows, macOS, and Linux. A real PTY
  is not required for `exec_command` plus `write_stdin` behavior.
- Token-limited reads are paginated while retained output is available. Output
  is removed only after the terminal result has been fully collected.
- The plugin test suite passes with 25 test files and 132 tests, including the
  large-output regression that originally exposed this failure.

## Performance

- Removing the real PTY/ConPTY startup path from normal commands eliminates the
  PTY initialization and Windows input-grace overhead for trivial executions.
- In the local Windows smoke check, trivial `exec_command` latency improved
  from roughly 3.5 seconds with the PTY path to roughly 0.3 seconds with the
  pipe path. This is an observed development measurement, not a platform-wide
  benchmark or a guarantee of sub-100 ms latency.
