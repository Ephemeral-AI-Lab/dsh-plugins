# 0.1.3

## Added

- Commands that exceed `yield_time_ms` are automatically registered with
  `ctx.jobs` as `codex-shell-N` jobs. `exec_command` returns that single ID,
  and `write_stdin`, `job_list`, and `job_kill` all use it.
- `job_list` reports running and terminal state, and `job_kill` terminates the
  underlying command session.

## Fixed

- Completion notifications steer the owner and direct output collection to
  `write_stdin`; a running owner consumes the notice at its next step, while an
  idle owner wakes in a new turn. The generic `job_output` notice is marked
  reported without consuming terminal output, and `followup` is never used.
- Completion delivered by `exec_command` or `write_stdin` inside that call's
  yield suppresses the redundant background steer. Completion between
  tool calls still sends exactly one notice.
- Owner and service teardown suppress completion steering instead of waking an
  agent being disposed with a misleading terminal notice.
- Successful terminal polls now render exit code 0 visibly.
- Repeated empty polls of a collected promoted session return its terminal
  status and `no unread output remains` instead of an unknown-session error.

## Behavior

- Codex Shell has no `run_in_background` parameter. Promotion happens only
  when a command remains live after the effective `yield_time_ms`.
- `ctx.jobs` tracks lifecycle and cancellation only. `write_stdin` remains the
  only command-output and interactive-input path.
